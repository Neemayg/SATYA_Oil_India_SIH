## 2. Closed-Vocabulary Activity ID Guardrail Architecture (Rule 5)

To guarantee compliance with **Rule 5** (LLM must NEVER invent a schedule Activity ID), the AI Architecture enforces a strict post-processing dictionary validator:

```
[Candidate Match Generated by AI] ──> [Closed Vocabulary Dictionary Check]
                                               │
                       ┌───────────────────────┴───────────────────────┐
                       ▼                                               ▼
          (Activity ID Exists in Baseline)             (Activity ID NOT in Baseline)
                       │                                               │
                       ▼                                               ▼
               [Accept Candidate]                          [FORCE "UNMATCHED" STATUS]
                                                           [Log Violation & Alert]
```

1. **Dictionary Binding:** When a schedule is ingested, all valid `activity_id` strings are compiled into an immutable set $V_{\text{valid}} = \{\text{ACT-1001}, \text{ACT-1002}, \dots\}$.
2. **Schema-Constrained Generation:** Structured parsing schemas strictly constrain output fields.
3. **Hard Post-Filter:** If the AI model returns any ID $a \notin V_{\text{valid}}$, the system discards the candidate ID, sets status to `UNMATCHED`, and records an audit flag: `AI_Hallucinated_ID_Blocked`.

## 3. Layered Schedule-Aware Matching Engine Strategy

Matching is executed in 7 sequential stages:

* **Stage 1 (Deterministic Filtering):** Filter out activities belonging to different projects, non-matching disciplines, or inactive temporal windows.
* **Stage 2 (Fuzzy Lexical Distance):** Compute Levenshtein / Token-Sort ratio between field text and baseline names/aliases.
* **Stage 3 (Semantic Vector Retrieval):** Query high-dimensional vector embeddings of Activity Fingerprints for semantic similarity.
* **Stage 4 (Spatial Chainage Interval Check):** Check if field chainage $[S_{\text{obs}}, E_{\text{obs}}]$ falls within activity chainage bounds $[S_{\text{act}}, E_{\text{act}}]$.
* **Stage 5 (WBS Topology & Predecessor Check):** Verify whether predecessor activities are completed before matching actual start.
* **Stage 6 (Multi-Factor Confidence Assessment):** Synthesize component scores into normalized confidence metric $[0.0, 1.0]$.
* **Stage 7 (Outcome Classification):** Classify match into `MATCHED`, `AMBIGUOUS`, `UNMATCHED`, or `CONFLICTED`.
